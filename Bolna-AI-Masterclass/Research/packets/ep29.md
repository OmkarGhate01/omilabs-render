# Packet: Ep 29 Transferring Live Calls to Humans

## Transfer Live calls to human agents with Bolna voice AI (tool-calling/transfer-calls)

Learn how to transfer live phone calls to human agents or custom endpoints using Bolna Voice AI. Enable seamless handoffs based on conversation context.

## What is call transfer?

Call transfer enables your Voice AI agent to route live calls to human agents, specific phone numbers, or your own SIP trunk based on conversation context. Essential for escalations, specialized support, or when human intervention is needed.

## Configuration options

| Setting | Description |
| - | - |
| **Description (Prompt)** | Tell the LLM when to trigger the transfer. Be specific - e.g., *"Transfer when caller requests to speak with a human agent or sales team."* |
| **Transfer destination** | A phone number in international format (e.g., `+19876543210`), or a SIP URI pointing at your own trunk (e.g., `sip:1234@sbc.example.com`). See [Transfer to a SIP trunk](#transfer-to-a-sip-trunk). |
| **Pre-tool message** | What the agent says while transferring - e.g., *"Sure, I'll transfer the call for you. Please wait a moment."* Supports multiple languages. |
| **Pre-call webhook** | Optionally notify a URL of your choice *before* the transfer happens — useful for sending the transfer reason to your system in real time. See [Pre-call Webhook](#pre-call-webhook). |

  The pre-tool message has one tab per language configured on the agent's [Languages tab](/docs/agent-setup/audio-tab), so multilingual callers hear the handoff in their own language.

## Transfer to a SIP trunk

An agent on [Plivo](/docs/plivo) telephony can transfer a call straight to your own SIP trunk instead of a phone number. Set the destination to a SIP URI and the call is delivered to that trunk.

```json theme={"system"}
{
  "call_transfer_number": "sip:1234@sbc.example.com"
}
```

SIP trunk transfer is available on Plivo telephony. On an agent using any other telephony provider, a transfer tool with a SIP URI destination does not fire, and the agent dashboard marks the tool accordingly.

### Custom SIP headers

Alongside the destination, a transfer tool can carry custom SIP headers. Each header is delivered on the outgoing INVITE with the name exactly as you write it, which lets your trunk route or annotate the call.

```json theme={"system"}
{
  "call_transfer_number": "sip:1234@sbc.example.com",
  "sip_headers": {
    "AccountId": "48219",
    "Segment": "gold",
    "OrderId": "%(order_id)s"
  }
}
```

Header values support the same `%(field)s` [substitution syntax](/docs/tool-calling/custom-function-schema#5-format-specifiers) used elsewhere, resolved from the variables you pass when placing the call. A variable the call does not supply resolves to an empty string, so pass every variable your headers reference.

Headers must satisfy the following, and any header that does not is left off the INVITE:

| Rule | Detail |
| - | - |
| Name characters | Letters and digits only |
| Name length | 24 characters at most |
| Value characters | Any character except a comma or an equals sign |
| Value length | 120 characters at most |

  Header values are delivered exactly as written, with no encoding applied, so your trunk reads them verbatim.

### UI configuration

In the agent dashboard, the Transfer Call configuration modal offers a **Transfer destination** choice between a phone number and a SIP trunk URI when the agent runs on Plivo telephony. Choosing **SIP trunk (URI)** reveals the URI field and a **Custom SIP headers** list where each row is a header name and value. Values accept `%(field)s` placeholders, and a picker inserts the variables your agent already references.

## Pre-call webhook

The Transfer Call tool can fire an optional **pre-call webhook** — a notification sent to a URL of your choice *before* the call is transferred. A common use case is sending the transfer reason to your system so a human agent has context the moment the call connects.

  The pre-call webhook is **fire-and-forget**. A slow or failing webhook endpoint never blocks or delays the transfer itself.

Two optional fields control the webhook:

| Field | Purpose |
| - | - |
| `pre_call_webhook_param` | The JSON body template to send, with `%(field)s` substitution. This is the on/off switch — if it is not set, no pre-call webhook fires. |
| `pre_call_webhook_url` | Where to send the webhook. If left blank, the agent-level [Webhook URL](/docs/post-call/polling-call-status-webhooks) is used instead. |

### Available substitution fields

`pre_call_webhook_param` is a JSON template. You can reference the transfer tool's runtime arguments using the same `%(field)s` [substitution syntax](/docs/tool-calling/custom-function-schema#5-format-specifiers) used elsewhere. The Transfer Call tool exposes:

| Field | Description |
| - | - |
| `%(reason)s` | Why the caller is being transferred, as determined by the LLM. |
| `%(summary)s` | A short summary of the conversation so far. |
| `%(call_transfer_number)s` | The destination number the call is being transferred to. |
| `%(call_sid)s` | The telephony provider's call identifier. |

  Any field that is not available at transfer time is sent as an empty string rather than failing the substitution.

```json theme={"system"}
{
  "pre_call_webhook_url": "https://your-api.com/pre-transfer-hook",
  "pre_call_webhook_param": {
    "transfer_reason": "%(reason)s",
    "conversation_summary": "%(summary)s",
    "transferred_to": "%(call_transfer_number)s",
    "channel": "voice"
  }
}
```

Static values (like `"channel": "voice"` above) are passed through as-is; `%(field)s` placeholders are substituted with the transfer tool's runtime arguments.

### What your endpoint receives

The webhook body is the **same execution record** you receive on the [post-call execution webhook](/docs/post-call/polling-call-status-webhooks) (execution id, agent id, telephony details, status, etc.), merged with the fields from your `pre_call_webhook_param`:

```json theme={"system"}
{
  "id": "<execution_id>",
  "agent_id": "<agent_id>",
  "status": "in-progress",
  "telephony_data": { "...": "..." },
  "...": "...",

  "transfer_reason": "caller asked for billing support",
  "conversation_summary": "Caller could not resolve a billing issue with the agent.",
  "transferred_to": "+19876543210",
  "channel": "voice"
}
```

  Because the call is still in progress when the pre-call webhook fires, fields that are only finalized at call end (transcript, cost, summary) won't be complete yet.

### URL resolution rules

| `pre_call_webhook_param` | `pre_call_webhook_url` | Result |
| - | - | - |
| Set | Set | Webhook sent to the transfer tool's `pre_call_webhook_url`. |
| Set | Not set | Webhook sent to the **agent-level Webhook URL** (the same URL used for post-call execution webhooks). |
| Not set | Set or not set | **No pre-call webhook fires.** |

  **`pre_call_webhook_param` is the master switch.** If it is not set, no pre-call webhook fires — even if `pre_call_webhook_url` is configured. The agent's normal post-call webhook is unaffected.

  **Agent-level URL fallback:** when `pre_call_webhook_param` is set without a `pre_call_webhook_url`, the pre-call webhook is sent to your agent's configured [Webhook URL](/docs/post-call/polling-call-status-webhooks). If you already use that endpoint for post-call execution webhooks, it will now also receive pre-call webhooks. Distinguish them by the in-progress `status` and the extra fields from your `pre_call_webhook_param`.

### UI configuration

In the agent dashboard, the Transfer Call configuration modal has a **Send a pre-call webhook before transfer** toggle. Turning it on reveals two inputs:

* **Pre-call webhook URL** — the endpoint to notify (`pre_call_webhook_url`). Leave blank to use the agent-level Webhook URL.
* **Pre-call webhook parameters** — the JSON body template with `%(field)s` substitution (`pre_call_webhook_param`).

Both save with the transfer tool and round-trip on edit.

## How to set up call transfer

**Open Tools Tab**:
    Navigate to the [Tools Tab](/docs/agent-setup/tools-tab) in your agent configuration.

**Add Transfer Call**:
    Find **Transfer Call** in the tool catalog and click **Add**.

**Configure the Destination**:
    Enter the phone number where calls should be transferred. On Plivo telephony you can instead choose **SIP trunk (URI)** and enter a SIP URI with optional [custom SIP headers](#transfer-to-a-sip-trunk).

**Write a Clear Description**:
    Describe when the transfer should trigger - e.g., *"Transfer when caller asks for sales, pricing, or demos."*

**Add Pre-tool Message**:
    Set the message your agent speaks while initiating the transfer.

**(Optional) Enable a Pre-call Webhook**:
    Toggle **Send a pre-call webhook before transfer** to notify your system *before* the transfer happens — see [Pre-call Webhook](#pre-call-webhook).

**Save Configuration**:
    Click **Save transfer call** to apply your settings.

  **Multiple departments?** Add separate transfer functions for Sales, Support, Billing - each with its own phone number and trigger description.

## Example conversation

**Caller requests human agent**:
    **Caller**: "I'd like to speak with someone from your sales team."

    **Agent**: "Sure, I'll transfer you to our sales team. Please wait a moment..."

    *Agent triggers transfer\_call function → Call is routed to configured sales number*

## Best practices

**Be specific**:
    Use detailed descriptions like *"Transfer to sales when caller asks about pricing, demos, or purchasing"* instead of generic "Transfer call"

**Test phone numbers**:
    Verify destination numbers are correct and always reachable before deploying

**Use pre-tool messages**:
    Always set a friendly message so callers know they're being transferred

**Handle failures**:
    Have a fallback plan if the destination is busy or unavailable

  **Test before deploying!** Failed transfers frustrate callers. Always verify phone numbers are correct and reachable.

## The call transfer did not work (troubleshooting/call-transfer-failed)

Fix Bolna call transfers that never fire, fail to connect or drop the caller: tool descriptions, destination format, SIP URI support and provider limits.

Split the problem in two before changing anything: did the **agent try** to transfer, or did the **transfer fail**? The transcript in [Call history](/docs/agent-setup/call-history) answers this — if the pre-tool message ("I'll transfer you now") was spoken, the tool fired.

## The agent never tried to transfer

**Sharpen the tool description**:
    The **Description (Prompt)** on the transfer tool is what the LLM matches against. Vague text produces missed transfers. Be explicit: *"Transfer when the caller asks for a human, a manager, or the sales team, or when they are angry."* See [Transfer a call to a human](/docs/tool-calling/transfer-calls).

**Confirm the tool is attached to this agent**:
    Tools are configured per agent on the [Tools tab](/docs/agent-setup/tools-tab). An agent copied before the tool was added will not have it.

**Check the prompt is not fighting the tool**:
    A system prompt instructing the agent to "always resolve the query yourself" will suppress transfers. Say when to hand off, not only when to help.

## The transfer fired but the call did not connect

**Check the destination format**:
    A phone number must be in international format — `+19876543210`. A national-format number is the most common failure.

**If transferring to a SIP URI, check the provider**:
    SIP-URI transfer (`sip:1234@sbc.example.com`) is supported on **Plivo** telephony. On other telephony providers a transfer tool with a SIP destination does not fire, and the agent dashboard marks the tool accordingly. See [Transfer to a SIP trunk](/docs/tool-calling/transfer-calls#transfer-to-a-sip-trunk).

**Verify the destination can actually receive the call**:
    Call the destination number directly from an ordinary phone. A number that is out of hours, unregistered, or blocked by the carrier fails the same way regardless of Bolna.

**Read the hangup fields**:
    `hangup_by` and `hangup_code` on the execution show whether the transfer leg was rejected by the carrier or the destination. See [Hangup codes](/docs/post-call/list-phone-call-hangup-status).

## The caller heard silence during the transfer

Set a **pre-tool message** on the transfer tool so the agent explains what is happening, and add one per language for multilingual agents. Transfers take a few seconds to bridge; without a message, callers hang up first.

## Getting the transfer reason into your systems

Use the **pre-call webhook** on the transfer tool to notify your own URL *before* the transfer bridges, and custom **SIP headers** to carry context onto the outgoing INVITE for your trunk to route on. Both are documented in [Transfer a call to a human](/docs/tool-calling/transfer-calls).
