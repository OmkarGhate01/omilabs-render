# Packet: Ep 53 What's New in Bolna (Rolling Changelog Episode)

## Bolna AI Updates for October, 2026 (changelog/october-2026)

October 2026 Bolna changelog: Bolna in Claude's connector directory, web search for voice agents, per-value definitions and post-call values for graph agent extraction, AssemblyAI session settings and agent context, and keyword biasing for Sarvam saaras:v4 speech-to-text.

**9th October, 2026**:
  ## Bolna is now a Claude connector

  Bolna is listed in Claude's connector directory, so you can manage your voice agents from a Claude chat without an API key or a config file. Open the [Bolna connector](https://claude.ai/directory/bolna), click **Connect**, and sign in with your Bolna account.

  * **Where it works:** Claude on the web, desktop and mobile
  * **What it can do:** create, inspect, update and delete agents, read call executions and batches, and check your account
  * **What it can't:** place calls or manage phone numbers, knowledge bases, dispositions, SIP trunks, sub-accounts or workflows. For those, connect the full MCP server at `https://mcp.bolna.ai/api/mcp`

  The Bolna MCP and Skills pages also have shorter URLs now, such as [bolna.ai/docs/mcp-server](/docs/mcp-server) and [bolna.ai/docs/skills](/docs/skills). Old links redirect.

  [Claude connector](https://claude.ai/directory/bolna) · [MCP server](/docs/mcp-server) · [MCP quickstart](/docs/mcp-quickstart)

**8th October, 2026**:
  ## Web search for voice agents

  Agents can now look up current information on the web during a call, so callers get answers about news, prices, scores and anything else that changes after a model is trained. Add the new **Web Search** tool from the Tools tab, and the agent searches only when a question needs it.

  * **Providers:** choose **OpenAI**, **Exa**, **Firecrawl** or **Parallel** as the search provider
  * **API keys:** OpenAI needs no key, since the agent uses its own OpenAI key if it runs on one, otherwise Bolna's. Exa, Firecrawl and Parallel use your own key from that provider
  * **Settings:** set a pre-tool message for the agent to say while it searches, and how many results it reads before answering
  * **Over the API:** configure it with `web_search` in the agent's `tools_config`

  [Web search](/docs/tool-calling/web-search) · [Tools Tab](/docs/agent-setup/tools-tab)

**8th October, 2026**:
  ## Define what a graph agent extracts, and get the values after the call

  Graph agent edges that extract values now take a definition for each value, and the values a call collected can be returned on the execution and webhook.

  * **Per-value definitions:** an extract parameter can carry a `description` that the routing model sees on that key and, for text values, `allowed_values` that the answer must come from, so expression edges can match one exact value
  * **In the dashboard:** each parameter in the edge inspector's **Extract parameters** section has **What to extract** and **Allowed values** fields
  * **Values after the call:** `node_extracted_data` on the execution and webhook holds the latest value per key the call collected
  * Reserved names (`reasoning`, `confidence`, `recipient_data`, `detected_language`, and names starting with `_`) are now rejected when an agent is saved

  [Inline data extraction](/docs/graph-agent/edges-and-routing#inline-data-extraction) · [Get execution](/docs/api-reference/executions/get_execution)

**7th October, 2026**:
  ## AssemblyAI session settings and agent context

  AssemblyAI agents can now tune how AssemblyAI ends the caller's turn and handles noise, and AssemblyAI now hears what your agent just said before the caller answers it.

  * **Agent context:** on the Universal-3 models, Bolna gives AssemblyAI the agent's last spoken reply as context for the caller's next turn, which helps on short answers, spelled-out names and numbers. It is automatic, and after a barge-in it uses only the part of the reply the caller heard
  * **Session settings:** a new `assemblyai_config` on the transcriber sets `mode`, `min_turn_silence`, `max_turn_silence`, `interruption_delay`, `vad_threshold` and voice focus. Each is optional and keeps AssemblyAI's default when unset
  * **In the dashboard:** **Mode**, **VAD threshold** and **Longest pause in a turn** are under **Advanced settings** in the Transcription section of the Languages tab, next to the Deepgram Flux and OpenAI settings, which moved there too
  * **Long contexts in any script:** a `context` of up to 1,750 characters now works in Hindi and other non-Latin scripts too; long non-Latin contexts used to fail to connect

  [AssemblyAI transcriber](/docs/assemblyai) · [Languages Tab](/docs/agent-setup/audio-tab)

**2nd October, 2026**:
  ## Keyword biasing for Sarvam speech-to-text

  Sarvam's `saaras:v4` transcriber now reads your agent's `keywords`, so the brand names, places and product terms your Indian-language callers say are recognised instead of the nearest common word. Until now Sarvam took only `context`; on `saaras:v4` you can set both.

  * Add terms in the **Keywords** box in your agent's Languages tab, or pass `keywords` on the transcriber over the API
  * Up to 50 terms of up to 64 characters each, and a list over either limit is rejected when you save the agent
  * `saaras:v3` and older Sarvam models have no keyterm support, so the box stays disabled there; keywords already saved on the agent apply once you move it to `saaras:v4`

  [Sarvam transcriber](/docs/sarvam-transcriber) · [Keywords and context](/docs/customizations/asr-keywords-and-context)

## Bolna AI Updates for September, 2026 (changelog/september-2026)

September 2026 Bolna changelog: start calls in a chosen language, Eleven v4 Turbo, AssemblyAI Universal-3, Soniox TTS and workflow webhooks.

**30th September, 2026**:
  ## Start a multilingual call in a chosen language

  A multilingual agent no longer has to open every call in its default language. When you know the customer's likely language, start that call in any language the agent has configured. The starting transcriber, voice and per-language prompt switch together, the welcome message is spoken in that language's voice, and mid-call switching works as before.

  * On the API, pass `"agent_data": { "language": "hi" }` to `POST /call` or the web-call session mint
  * Everywhere else, set an `agent_language` variable: a batch CSV column, inbound caller data, a SIP header mapping, a workflow variable, or `user_data` on `/call`
  * Invalid languages are rejected with a `400` on `/call` and web calls, and mark only that row as `error` in a batch; inbound calls and workflows fall back to the default language
  * On single-language agents, `agent_language` stays an ordinary prompt variable, so existing calls are unaffected

  [Start a call in a chosen language](/docs/customizations/start-call-in-language)

**29th September, 2026**:
  ## Eleven v4 Turbo is available for voice agents

  ElevenLabs' newest model, **Eleven v4 Turbo**, can now be selected as a synthesizer. It is built for real-time conversation, at a median inference latency of about 100 ms, and supports **74 languages**, including Hindi, Tamil, Bengali, Marathi, Gujarati, Kannada, Malayalam, Telugu and Punjabi.

  * Pick **Eleven v4 Turbo (Beta)** from the ElevenLabs model dropdown in your agent's Languages tab, or pass `eleven_v4_turbo` as the model over the API
  * Almost every ElevenLabs voice in Bolna works with it; the few that do not render on v4 are left out of its voice list
  * Like Eleven v3, it ignores `speed`, `style` and `similarity_boost`, and `temperature` maps to three stability presets (`0.0` creative, `0.5` natural, `1.0` robust)

  Turbo v2.5 remains the default and the lower-latency option.

  [ElevenLabs voice synthesis](/docs/elevenlabs-voice)

**29th September, 2026**:
  ## AssemblyAI Universal-3 models

  `universal-3-6-pro` and `universal-3-5-pro` replace the English-only engine Bolna was pinned to, and both accept `keywords` and `context` together. Use `universal-3-6-pro`: against `universal-3-5-pro` it makes 45% fewer errors on short answers like "yes" or "no thanks", leaks 22% less background speech into the transcript, and covers 32 languages rather than 19, at the same latency and the same price.

  The legacy `universal` model is deprecated and no longer selectable on new agents. Existing agents keep running on it; move them to `universal-3-6-pro` when you next edit them.

  [AssemblyAI transcriber](/docs/assemblyai) · [Keywords and context](/docs/customizations/asr-keywords-and-context)

**26th September, 2026**:
  ## Extra request params for custom LLMs

  Agents running on a [custom LLM](/docs/custom) can now send your server parameters beyond the OpenAI standard. The most common use is turning a reasoning model's thinking off, which removes the silence it adds before every reply:

  ```json theme={"system"}
  "extra_body": { "chat_template_kwargs": { "enable_thinking": false } }
  ```

  * Set per agent under **Intelligence → Extra request params**, with one-click examples for vLLM/SGLang and OpenRouter, or as `llm_config.extra_body` over the API
  * Sent on every request to your endpoint, including graph agent routing and the end-of-call and voicemail checks
  * Saving is refused for non-custom providers and for keys Bolna controls, such as `model`, `messages` or `tools`
  * Bolna no longer sends `service_tier` to custom endpoints, so strict OpenAI-compatible servers that rejected it now work

  [Extra request params](/docs/custom#extra-request-params)

**23rd September, 2026**:
  ## Callers can interrupt the goodbye

  When your agent decides a conversation is over, callers often cut in with one last question just as it says goodbye. Until now the agent ignored them, finished its goodbye and hung up. Turn on **Allow interruption** under **Engine → Final Call Message** and the agent stops, cancels the hangup, and answers instead.

  * Off by default, so existing agents behave exactly as before
  * Applies when the agent ends the call through the hangup prompt; silence, call-timeout, transfer and voicemail hangups still end the call
  * Available through the API as `interruptible_hangup_message` in the agent's `task_config`

  [Final Call Message & Call Management](/docs/agent-setup/engine-tab#final-call-message-%26-call-management)

**23rd September, 2026**:
  ## Soniox joins Bolna as a new voice synthesizer

Its real-time `tts-rt-v2` model speaks 63 languages — including ten Indian languages — from a single model, with 200 named voices. Soniox is also available as a [transcriber](/docs/soniox), and one `SONIOX` key serves both.

  * Runs over a persistent WebSocket, so model output is spoken as it streams in rather than in fixed chunks

**22nd September, 2026**:
  ## 🔔 Workflow execution webhooks

  A workflow can now POST to your server every time an execution finishes, so you no longer have to poll for outcomes. One request per contact, sent the moment that contact's journey ends.

  * Set the webhook URL and headers in the workflow's `settings` through the [Update Workflow API](/docs/api-reference/workflows/update). Updates are merged, so you can add or remove a single header without resending the others
  * The payload carries `status`, `outcome`, `termination_reason` and a `trail` of every node the contact passed through, with the branch each one took
  * Executions that end without reaching an end node — cancelled, aborted, or failed — report too
  * Missed a delivery? The [Resend Webhook API](/docs/api-reference/workflow-webhooks/resend) sends it again with the original payload

  [Test the destination](/docs/api-reference/workflow-webhooks/test) before running anything. The sample is walked from your own published graph, so it carries your node ids and your extraction field names rather than placeholder data, and the response tells you whether your server was reached and what it replied.

  Return a 2xx as soon as you have accepted the payload. See [Execution webhook](/docs/workflows/execution-webhook) for the full contract.

**20th September, 2026**:
  ## 🎯 Keyword and context biasing for speech-to-text

  Voice agents mishear the words that matter most: brand names, SKUs, the name of your own company. Two transcriber fields bias recognition towards your vocabulary, in the agent's **Audio** tab and through the API.

  * `keywords`, the comma-separated term list, is now honoured by seven providers rather than two: [Deepgram](/docs/deepgram-transcriber), [AssemblyAI](/docs/assemblyai), [Soniox](/docs/soniox), [Azure](/docs/azure-transcriber), [Smallest](/docs/smallest-transcriber), [ElevenLabs](/docs/elevenlabs-transcriber) and [Gladia](/docs/gladia)
  * `context` is new. A sentence or two describing the call, supported by [AssemblyAI](/docs/assemblyai), [Soniox](/docs/soniox) and [Sarvam](/docs/sarvam-transcriber)

  "I am calling about my Plivo and Exotel setup on Bolna" transcribes as "clivo and exodel setup on valna" unbiased, and correctly with those three names in `keywords`.

  Per-term weights (`Bolna:5`) reach the engines that support them and are stripped for the rest. Fields a provider cannot use are shown disabled rather than hidden.

  [Keywords and context](/docs/customizations/asr-keywords-and-context) · [Audio tab](/docs/agent-setup/audio-tab) · [Create Agent API](/docs/api-reference/agent/v2/create)

  ## 📘 Create Agent API reference now covers every provider

  The [Create Agent API](/docs/api-reference/agent/v2/create) reference documented a fraction of what the API actually accepts — two transcribers and four synthesizers. It now lists the full set, with the exact `provider` and `model` values each one takes:

  * **11 transcribers** — Deepgram (including Flux), Sarvam, OpenAI, Azure, ElevenLabs, AssemblyAI, Gladia, Smallest, Soniox, Gemini and Google

**4th September, 2026**:
  ## Extraction categories API

  Extraction categories are now first-class API objects. A category is the set of dispositions evaluated together in a single LLM pass — one category means one LLM call per conversation — and the category owns the model used for that pass.

  New endpoints:

  * `POST /agent/{agent_id}/extraction-categories` — create a category (name + model) and attach it to an agent
  * `GET /agent/{agent_id}/extraction-categories` — list an agent's categories with their dispositions
  * `PATCH /extraction-categories/{category_id}` — rename a category or change its model; renames propagate to all its dispositions
  * `DELETE /extraction-categories/{category_id}` — delete a category and all of its dispositions

  The disposition endpoints accept `category_id` (preferred) alongside the existing `category` name — a name that does not match one of the agent's categories creates a fresh category — and every disposition response includes `category_id`. Move a disposition between categories by updating it with a new `category_id`; a category emptied by a move or delete is removed automatically.

  ## Call summary toggle

  * Call summaries are an agent-level toggle: `call_summary_enabled` (boolean, off by default) on the agent create and update APIs and in agent responses. When on, a platform summary pass runs after each call and writes the summary to the execution's `summary` field and to `extracted_data` under `General > Call Summary` with only a `subjective` value; agents with the toggle off produce no call summary.

  [Extraction Categories API](/docs/api-reference/extraction-categories/overview) · [Dispositions API](/docs/api-reference/dispositions/overview) · [Using Extractions](/docs/prompting/using-extractions)

**1st September, 2026**:
  ## 🌐 More accurate language switching for multilingual agents

  If your voice agent speaks more than one language, it's now much better at telling when a caller has *actually* switched languages, instead of reacting to a single stray word.

  **Before:** one borrowed word — like an English word inside a Hindi sentence — could make the agent switch languages by mistake.

  **Now:**

  * The agent only switches when the caller speaks a full sentence in another language, or clearly asks for one by name.
  * Everyday things like "okay," a phone number, or an OTP no longer count as a language change, even mid-sentence.
  * If the agent misreads a word, it recovers on the caller's next turn instead of staying stuck in the wrong language.

  This works automatically for every multilingual agent — no setup changes needed.

  📘 [How Language Switching Works](/docs/customizations/language-switching-behavior)

**27th August, 2026**:
  ## 🔡 Nested JSON in prompt variables — and prompts containing JSON no longer break

  Prompt variables can now carry **whole JSON objects and arrays**, not just flat strings. Reach into them with a double-brace token and a dotted path:

  ```text agent prompt theme={"system"}
  Hi {{customer.name}}, you're on our {{customer.tier}} plan.
  Your last order {{orders.0.id}} is {{orders.0.status}}.
  Full trend data: {{score_trend}}
  ```

  A token like `{{score_trend}}` on its own renders the entire object as JSON, array elements are reachable by index, and a value that arrives as a *stringified* JSON blob is parsed for you. The first segment of a path must be a **top-level key** of the data you passed — paths mirror your JSON exactly, starting at the root.

  This works everywhere variables already did: `user_data` on [`/call`](/docs/api-reference/calls/make), `userData` in the [Web Call SDK](/docs/developer-resources/sdks/web-call#passing-user-data), the JSON returned by [incoming caller identification](/docs/customizations/identify-incoming-callers), and graph agent nodes.

  **Prompts that contain JSON are now safe.** Previously, a single JSON example pasted into a prompt could stop *every* variable in that prompt from being substituted, leaving the agent to read placeholders like `{full_name}` out loud. Braces that don't look like a variable path are now left untouched, so a JSON snippet and your variables can live in the same prompt.

  Existing single-brace `{variable}` prompts keep working unchanged. An unresolved `{{variable}}` stays visible in the prompt as `{variable}`, which makes a mismatched path easy to spot in the transcript.

  📘 [Adding variables](/docs/prompting/using-context#nested-json-variables)

**25th August, 2026**:
  ## Transfer a call to your own SIP trunk

  A Transfer Call tool on an agent using [Plivo](/docs/plivo) telephony can now hand the call to a SIP URI instead of a phone number, so escalations land on your own trunk rather than going back out over the PSTN.

  Each transfer tool can also carry custom SIP headers, delivered on the outgoing INVITE with the names exactly as you write them, which is what lets your trunk route or annotate the call. Header values take the same `%(field)s` placeholders used elsewhere, so they can carry per-call data such as an order or account id.

  ```json theme={"system"}
  {
    "call_transfer_number": "sip:1234@sbc.example.com",
    "sip_headers": {
      "AccountId": "48219",
      "OrderId": "%(order_id)s"
    }
  }
  ```

  In the dashboard, the Transfer Call modal offers a **Transfer destination** choice between a phone number and a SIP trunk URI, with a list for the headers and a picker for your agent's variables.

  [Transfer to a SIP trunk](/docs/tool-calling/transfer-calls#transfer-to-a-sip-trunk)

**12th August, 2026**:
  ## Eleven v3 is available for voice agents

  ElevenLabs' most expressive model, `eleven_v3_conversational`, can now be selected as a synthesizer. It supports **74 languages**, including Hindi, Tamil, Bengali, Marathi, Gujarati, Kannada, Malayalam, Telugu and Punjabi, and every ElevenLabs voice available in Bolna works with it.

  One thing to know before switching an agent over: `speed`, `style` and `similarity_boost` have no effect on v3, and `temperature` maps to three stability presets (`0.0` creative, `0.5` natural, `1.0` robust).

  Turbo remains the default and the lower-latency option.

  [ElevenLabs voice synthesis](/docs/elevenlabs-voice)

  Bolna now supports Sarvam's **saaras:v4** transcriber model — the latest Saaras speech-to-text model, transcribing directly in the original spoken language with automatic language detection support. Supports all 11 Indian languages.

**6th August, 2026**:
  ## 🔌 Bolna joins viaSocket's app directory

  If you build automations in [viaSocket](https://viasocket.com/integrations/bolna), Bolna is now a first-class app you can drop into any flow — connect your API key once, no custom code needed.

  Six actions are live today:

  * **Make a Phone Call** — kick off an outbound call from any workflow
  * **Get All Executions** — pull call history and details into your flow
  * **List Voice AI Agents** — see every agent on your account
  * **List Phone Numbers** — see every number on your account
  * **List Knowledgebases** — see every knowledge base on your account
  * **List Providers** — see every provider connected to your account

  📘 [viaSocket integration overview](/docs/tutorials/viasocket/overview) · [Create a Bolna API connection with viaSocket](/docs/tutorials/viasocket/create-bolna-api-connection)

**5th August, 2026**:
  ## 🛠️ The MCP server now controls nearly your whole account

  When the [Bolna MCP server](/docs/mcp-server) launched, it covered the basics — agents, calls, transcripts, account info. It's grown into something closer to a full remote control. From the same chat window, you can now say things like:

  * "Buy me a US number and route it to my support agent" — search, purchase, and set up inbound call routing
  * "Create a batch campaign from this CSV and schedule it for 9am" — batches can now be created, scheduled, stopped, or deleted, not just listed
  * "Add a disposition that pulls appointment\_time out of every call" — structured, typed data out of every transcript
  * "Set up a SIP trunk for my Twilio account and attach these numbers" — bring your own telephony
  * "Cancel every queued call for this agent" — stop one call or a whole agent's queue
  * "What did my Acme Corp sub-account spend this month?" — check and manage sub-accounts, and switch between them mid-conversation with a key you already have on hand

  Anything that deletes something, spends money, or places a real call still pauses for your confirmation first, same as before.

  📘 [MCP Overview](/docs/mcp-server) · [Tool List](/docs/mcp-tool-list) · [Prompt Cheatsheet](/docs/mcp-prompts)

**3rd August, 2026**:
  ## 🎙️ Maya joins Bolna as a new voice synthesizer

  [Maya Research](https://www.mayaresearch.ai/)'s `Maya 2 Native` model is now available as a text-to-speech provider, with two voices — **Ananya** and **Arjun** — each covering all 11 supported languages, including Indian English.

  * Runs over a persistent WebSocket, so LLM output is spoken as it streams in rather than in fixed chunks
  * Language can switch mid-call without dropping the connection
  * Supports both telephony (mu-law) and web (native 24 kHz) audio

  📘 [Maya voice provider docs](/docs/maya)
