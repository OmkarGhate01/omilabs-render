# Packet: Ep 10 Interruptions, Silence and Endpointing (Engine Tab)

## Configure voice AI latency and interruptions (agent-setup/engine-tab)

Fine-tune your Bolna Voice AI agent's performance. Configure transcription accuracy, interruption thresholds, response latency, and user detection.

## What is the Engine tab?

The Engine Tab controls the core performance settings of your voice AI agent. Fine-tune transcription accuracy, interruption behavior, response timing, and user presence detection for optimal conversation quality.

## Configuration options

### Transcription & interruptions

Control how speech is captured and processed during conversations.

**Interruption threshold**:
    **Number of words to wait for before interrupting** — how many words the user must say before the agent treats it as an interruption and stops speaking.

  **Stopwords like "Stop", "Wait", "Hold On"** will always pause the agent immediately, regardless of the interruption threshold.

### Response latency

Configure how quickly your agent responds to user input.

| Setting | Description | Impact |
| - | - | - |
| **Response Rate** | Choose a preset or **Custom** | Presets tune latency automatically; Custom exposes the sliders below |
| **Endpointing (ms)** | Wait time before generating response | Lower = faster but may cut off user |
| **Linear Delay (ms)** | Accounts for mid-sentence pauses | Prevents premature responses |

  The **Endpointing** slider only appears for transcribers that use it: Deepgram (except Flux models), ElevenLabs, Gladia, OpenAI and Gemini. Other transcribers, including [Deepgram Flux](/docs/deepgram-flux), detect the end of a turn on their own, so the slider is hidden and a note under Response Latency explains why. **Linear Delay** still applies to every transcriber.

  **Lower latency isn't always better!** Setting values too low may cause the agent to interrupt users mid-sentence. Start with defaults and adjust based on testing.

  For **natural conversations**, use Endpointing around 200-300ms and Linear Delay around 400-500ms.

### User online detection

Detect when users go silent and automatically re-engage them.

**Enable Detection**:
    Toggle **User Online Detection** to check if the user is still on the call.

**Set the Message**:
    Customize the prompt (e.g., "Hello, are you still there?") per language using the language tabs.

**Configure Timing**:
    Set **Invoke message after (seconds)** to control when the check triggers.

  Set the timer between **8-15 seconds** to give users enough time to respond without seeming impatient.

### Final call message & call management

Configure the last message your agent says before disconnecting, and how and when calls should end.

**Final Call Message** — select a language, write a warm closing (e.g., "Thank you for your time. Goodbye!"), and repeat for each language your agent speaks.

**Allow interruption** lets the caller speak over the agent's goodbye. When the agent decides the conversation is over and starts to say goodbye, a caller who cuts in with a last question ("wait, one more thing") stops the goodbye, the hangup is canceled, and the conversation carries on. The agent can still end the call later. Off by default, so the goodbye plays through and the call ends.

  Allow interruption applies when the agent ends the call through [Hangup using a prompt](/docs/agent-setup/agent-tab#hangup-using-prompt). Hangup on user silence, total call timeout, call transfers and voicemail hangups are never interruptible. A caller can reopen the conversation at most twice per call; after that the goodbye plays through.

| Setting | Description | Recommended |
| - | - | - |
| **Hangup on User Silence** | Auto-hangup after X seconds of silence | 6-10 seconds |
| **Total Call Timeout** | Maximum call duration in seconds | 300s (5 min) for support, higher for sales |

  **Set reasonable timeouts** to manage costs and prevent stuck calls. Very long calls can indicate issues or abandoned calls.

## Best practices

**Start with defaults**:
    Use default settings initially and adjust based on real call feedback

**Test extensively**:
    Make test calls to experience the timing and interruption handling

**Consider use case**:
    Customer support may need longer pauses; sales may prefer faster responses

**Monitor analytics**:
    Review call recordings to identify timing issues

## The agent interrupts or talks over the caller (troubleshooting/agent-interrupts-users)

Fix a Bolna agent that cuts callers off, or won't stop talking when interrupted, by tuning endpointing, linear delay and the interruption threshold.

Two opposite complaints share one set of settings, all on the [Engine tab](/docs/agent-setup/engine-tab).

## The agent cuts the caller off mid-sentence

The agent decided the caller had finished speaking when they had not — usually because they paused to think, or read out a number in chunks.

**Raise Linear Delay**:
    Linear delay exists specifically to absorb mid-sentence pauses. Try **400–500 ms** as a starting point and increase for callers who dictate numbers or addresses.

**Raise Endpointing**:
    Endpointing is how long the agent waits after speech stops before responding. **200–300 ms** suits natural conversation; below that the agent will clip people.

**Move off the Fast response rate preset**:
    If the agent is on **Fast**, switch to **Balanced** or **Custom** and tune the two values above. Fast trades conversational safety for speed.

**Re-test with a real caller, not a clean read**:
    Have someone dictate a 12-digit number and a street address. Those are the cases that expose aggressive endpointing.

## The agent keeps talking when the caller interrupts

**Lower the interruption threshold**:
    The threshold is the **number of words** the caller must say before Bolna treats it as an interruption. A high value makes the agent stubborn; lower it so short interjections land.

**Check whether background noise is being transcribed**:
    A threshold set low enough to catch "stop" will also catch a TV in the background. Enable **noise cancellation** on the [Call tab](/docs/agent-setup/call-tab) before lowering the threshold further.

  Stopwords such as **"stop"**, **"wait"** and **"hold on"** always pause the agent immediately, whatever the interruption threshold is set to.

## If tuning does not settle it

* The agent may be responding slowly rather than interrupting — the caller starts a second sentence into the gap and collides with the reply. Check [Responses feel slow](/docs/concepts/latency) and the [per-call latency metrics](/docs/concepts/call-latencies).
* A long, list-heavy reply is more likely to be interrupted. Instruct the agent to answer in one or two sentences — see [Write better prompts](/docs/prompting/introduction).
* Enable **Generate precise transcript** on the Engine tab while debugging, so the transcript shows exactly what the transcriber heard at the moment of the collision. See [Capture precise transcripts](/docs/customizations/capturing-precise-transcripts).
